# 来源与产物证据契约

本地适配层保留 shared kernel 0.1.0，不覆盖其版本化副本。平台适配、先规划后下载、逐字稿与成品分层、语义规划与确定性组装继续使用原流程。

## 音频

缓存必须有匹配的 `.m4a.receipt.json`：记录源身份/范围、输入 hash、输出 hash、解码与时长校验。FFmpeg 和下载先写唯一临时文件，成功校验后替换。旧非空文件没有校验记录时不作为 ready；重新物化会产生记录。混合块即使有拼接缓存，也恢复任务书要求的精确分腿。

清理检查完整 BlockPlan，不能用选择的几个块替代全体消费者。只有已完成、具有当前 `audio_release.json` 的工作区才能回收；只处理计划归属明确、校验记录有效的源音轨、块和分腿。未知音频与无记录旧缓存保留。`--keep-audio` 仍有效。

回收记录格式：`decision: approved`、非空 `reviewer` 和 `reason`，以及 `AudioMaterializer.release_dependencies(ws)` 返回的 `dependencies`。该方法只计算依赖，不产生批准。逐字稿、长文、笔记、教材或计划变化后批准失效；须先完成对应范围复核再更新记录，不能由生产结束事件自动盖章。

## 范围与内容

`check --production` 用 source.parts 的原分集时长与 units 的原分集秒区间检查缺口、重叠和越界，并交叉校验 segments 的拼接坐标与源偏移。缺失时长不能降级为“分集号出现即覆盖”。两位小数的计划以 start/end 为区间边界，不把独立四舍五入的 duration 再累计成边界。

公式断裂、自述泄漏为致命项，重复标题为提示项。实现按 MIT 上游 `730878a88fee4531b4e1c8a650a32ac6ad1aa177` 移入视频适配层，包含新规则回归；未引入自动全局公式替换。门禁只表达技术检查结果，不能证明数学题设、板书或讲解语义正确。

上游 CID 后缀搜索、短页豁免、非事务队列认领未合入。CID 迁移应提供验证过的 AID 映射；字幕身份与覆盖分别判断；并发派发需要覆盖整个读、选、写事务的锁或 lease。

## 发布

新 video publication 使用 schema 2，经 release 的 content_contract 校验。源身份、原分集秒区间、块、逐字稿、长文、教材/笔记、生成工具和规则版本形成显式依赖图。每个产品的技术验收与内容验收分别绑定依赖指纹、范围、限制及证据 hash。

课程和产品 UID 固定，`product_type` 显式声明；路径和标题只是展示属性。产品移动不改变内容指纹。修改来源只影响其依赖子图；改教材不自动撤销上游长文或独立笔记的验收。旧 schema 1 可读取固定历史交付，但不能给新 video 交付绕过契约。

只读上游库继续只读。待复核文件记录在容器 `state/content/quarantine.json`，发布锁冻结该状态；本地新增课程先记录范围与迁移映射，通过来源和内容验收后才能进入 owned。
